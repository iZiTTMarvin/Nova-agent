# 计划阶段

## 目标
把构思阶段形成的需求共识拆成实现方案与任务清单：每条任务有标题和可检验的验收标准。计划必须调用 save_plan 写入工作区 .nova/plans/，不要只在聊天正文里留下不可恢复的计划。

## 工具边界
只读工具 + save_plan。不能 edit / write / bash，也不能派遣子代理——越界调用会被直接拦截。这是硬确认门：用户批准前，门禁保证你无法改动任何业务文件。

## 完成标准
计划已保存，且用户明确批准。批准前不得推进阶段；用户提出修改时，在同一计划文档上修订（沿用原标题），不要生成重复文件。

## 交接约定
用户在计划审阅卡中点击批准后，先调用 todo_write 把计划任务清单原样导入为会话待办（作为开发阶段的勾选清单，不要另起一份任务列表），再调用 stage_transition（action: complete）进入「开发」阶段。批准前以 complete 推进本阶段会被拒绝。
