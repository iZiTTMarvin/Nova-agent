# 跨会话记忆读取

开启记忆后，Agent 使用 `memory_search` 查询项目事实、历史决策和用户偏好。开始项目任务或遇到新的报错时使用具体关键词检索；同一事实已经在当前对话中时直接复用。命中文件或符号后，在对应位置核对当前事实，避免重新遍历整个项目。

记忆读取复用普通工具链。结果只追加一次，后续请求按原样回放，由现有工具交付、会话持久化、恢复及压缩流程管理。请求前不插入、替换或移除临时记忆块；记忆数据库变化不会改写已有对话、system policy 或缓存路由。

这保证记忆读取不会主动破坏历史请求前缀，不代表新增工具调用没有 token 成本，也不保证供应商每次都命中缓存。缓存命中仍取决于服务端状态；实际比率以响应 usage 为准。工具说明的版本更新与其他静态工具定义变更一样，可能使升级后的首个请求重新建立缓存。

职责保持如下：

| 职责 | 所属模块 |
| --- | --- |
| 是否调用、如何使用历史线索 | Agent 根据工具说明与当前任务判断 |
| 查询构造、项目隔离、排序、失效校验 | Memory 检索模块 |
| 工具可用性、设置检查、结果格式化 | `memory_search` |
| 工具结果回放、恢复、上下文预算与压缩 | 现有 runtime 工具和会话链路 |
| 采集新证据与提炼候选 | ObservationCapture、MemoryExtractor |

中文与英文标识符混合的查询，回退检索优先保留完整英文词，再分配中文三字片段，防止长开场话术挤掉末尾错误码。没有使用向量库、额外模型检索或绝对 BM25 阈值；BM25 的数值随语料变化，不能直接视作固定的置信度。

记忆是历史证据。当前用户指令和工作区事实优先；observed 偏好只是参考。`memory_search` 自身产生的工具结果不作为新的采集证据，也不通过提炼重复强化旧记忆。已有提炼频率、晋升规则、数据格式和用户总开关保持原有行为。

验证入口：记忆单测、记忆 SQLite 集成评测，以及显式运行的 `tests/live/memoryUtility.spec.ts`。真实评测使用隔离项目，不读写用户的记忆库；需要 `MEMORY_AB_API_KEY`，运行会产生真实模型费用。运行前必须使用 Node ABI 的 better-sqlite3，结束后恢复 Electron ABI。
