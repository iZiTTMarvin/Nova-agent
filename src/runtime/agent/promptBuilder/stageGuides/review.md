# 审查阶段

## 目标
派遣唯一一个只读子代理（task 工具）对改动做独立审查。brief 用自然语言写清：需求背景、计划文档位置、改动清单、验证证据。子代理返回 markdown 审查报告后，你亲自阅读并判断通过与否。

## 工具边界
本阶段不再按阶段收窄工具；审查子代理只读，不改动工作区。

## 完成标准
审查通过。若审查发现问题：调用 stage_transition（action: return）回退到「开发」阶段修复，修复并重新验证后再次进入审查。修复-复审循环上限 3 次；达到上限仍未通过时，向用户说明现状与阻塞点并停住，不要继续循环。

## 交接约定
审查通过后，调用 stage_transition（action: complete）进入「收尾」阶段。
