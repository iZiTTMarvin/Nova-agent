# 模型思考控制

思考能力由 `src/shared/config/modelRegistry.ts` 的精确型号记录，`reasoning.ts` 负责选择与别名归一，`runtime/model/reasoningDialect.ts` 负责 Chat Completions 参数编码。设置、聊天、子代理和请求使用同一规则。

## 选择语义

- 模型设置的 `auto`：沿用服务商默认，不发送显式强度。已知默认仅用于说明和等待超时估算。
- 会话覆盖为 `null`：跟随模型设置；会话覆盖为 `auto`：明确使用服务商默认。
- 具体强度：发送归一后的强度；`enabled`/`none` 仅用于已确认支持的思考控制。
- 保留原滑块、样式和动画；轨道只展示具体选项，不增加 auto 节点。配置为 auto 时按已知服务商默认定位，例如默认 Max 就直接显示并选中 Max。没有可确认选项时不展示调节器。

GLM-5.2 的 Low/Medium 是 High 的接口别名，XHigh 是 Max 的别名，界面不重复展示。旧 MiniMax M2 的 High/Max 收敛为默认，M3 的 High/Max 收敛为开启；这些是已发布配置的读入兼容，在不再支持这些旧配置时可移除，回归由 `reasoning.test.ts` 保护。

主会话在启动、切换和模型刷新时通过同一元数据入口归一旧覆盖，变化后持久化。子代理预设在编辑草稿进入显示、校验与保存前归一；历史子代理保留出生 header，恢复配置和活动投影使用有效值。幂等重放按冻结型号比较归一后的覆盖，不能把参数别名当成不同命令。

开关轨道从左到右为关闭、开启。DeepSeek 编码入口的 `minimal` 映射为 Low，不表示关闭思考。

## 新型号维护

1. 核对对应服务商、协议和具体型号的官方文档，记录链接及核验日期。
2. 只登记真实可区分的强度、思考开关和已知默认，不按型号前缀继承未知版本。
3. 若使用现有协议编码，只补能力数据；只有请求字段确有不同才增加编码策略。
4. 用请求体契约测试验证每个真实档位、默认省略、关闭限制及历史别名；不同强度的请求路由应可区分。
5. 验证设置与会话覆盖，包括切换模型、重载、保存失败和子代理绑定；支持强度的型号必须显示 Low/Medium/High/XHigh/Max 中真实支持的值，不能统一显示开启。

官方文档核验不能代替真实 API 验证。第三方网关是否接受官方字段需要独立确认。当前没有远程能力更新或自动探测；MiMo 未确认的云端思考控制保留未知，不把本地 SGLang 模板参数当成云端 API 能力。

## 协议范围

这里只描述思考控制，不能据此推断工具或视觉能力。GPT-6 Astra 与 GPT-6.1 Sol 的官方 Chat Completions 工具调用限制仍受各自官方文档约束；Responses 协议适配不属于此模块。
